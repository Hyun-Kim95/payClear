# design-brief

## 목적

취향을 감으로 두지 않고, **그리기 전에 값을 숫자·근거·금지·시그니처로 고정**한다.  
이 산출물은 `65-design-gate`·이중 목업의 **사전 계약**이며, Gate 1/2나 디자인 HUMAN 승인을 대체하지 않는다.

**고객 E2E:** `client-project-lifecycle` **단계 2-0**에서 본 브리프 완성 전에는 2A/2B를 시작하지 않는다(하드 스톱). 생략은 사용자 명시 + 사유 기록만.

## 사용 시점

- `client-project-lifecycle` **단계 2-0** (이중 목업 전 **필수**)
- 랜딩·포트폴리오·프로모·마케팅 등 **첫인상이 전부인** 화면
- UI 신규인데 “어디서 본 것 같다”를 피해야 할 때
- `design-system-agent`가 토큰·톤을 잡기 전에 방향이 필요할 때

## 담당

- Owner: `design-system-agent` (축·토큰·시그니처)
- 입력 협력: `prd-agent` (목표·톤·금지 카피), 필요 시 `frontend-agent` (구현 가능성)
- Integration Owner: 메인 에이전트(브리프 → 2A/2B 동일 입력 공유)

## 절차

1. **surface**를 고른다: `landing` | `portfolio` | `marketing` | `product` | `dashboard`.
2. 아래 **축 표**를 채운다. 각 축에 **값(1–10)** + **한 줄 근거** + **구체 예시 1줄**(숫자의 체감)을 적는다.
3. **시그니처 1–2개**를 고른다(타이포 / 레이아웃 제스처 / 모션 / 색 중). 금지 목록만으로 무난함에 수렴하지 않게 한다.
4. **금지 목록**을 surface에 맞게 적용한다. 상세: [anti-patterns.md](anti-patterns.md).
5. `product` / `dashboard`면 랜딩용 모션·분산 기본값을 **그대로 쓰지 않는다**. 상태 UI(기본/로딩/빈/오류/권한) 축을 추가로 적는다.
6. 산출물을 `docs/design/design-brief-{slug}.md`에 저장한다. 뼈대: [template.md](template.md).
7. 이중 목업이면 **안 A·안 B가 동일 브리프**를 입력으로 쓰는지 확인한 뒤 2A/2B로 넘긴다.
8. HUMAN이 브리프를 수정하면 값을 갱신한 뒤에만 목업을 그린다.

## 디자인 축 (1–10)

| 축 | 의미 | 낮은 값 | 높은 값 |
|----|------|---------|---------|
| `DESIGN_VARIANCE` | 배치를 얼마나 흔들지 | 1 대칭·정돈 | 10 실험적 비대칭 |
| `MOTION_INTENSITY` | 움직임 강도 | 1–3 정지·페이드만 | 8–10 스크롤 연동·강조 모션 |
| `VISUAL_DENSITY` | 정보 밀도 | 여백·한 메시지 | 대시보드형 빽빽함 |
| `TYPE_EXPRESSION` | 타이포 표현 | 절제·본문 중심 | 디스플레이·대비 큼 |
| `COLOR_BOLDNESS` | 색 대담함 | 중성·단색 위주 | 강한 액센트·대비 |

축마다 반드시 **예시 1줄**을 붙인다. 예: `VISUAL_DENSITY=3` → “첫 뷰포트에 브랜드·한 줄·CTA만, 통계/카드 없음”.

## surface별 기본값 (시작점)

값은 출발점이다. 제품·브랜드에 맞게 조정하되, 조정 사유를 근거란에 남긴다.

| surface | VARIANCE | MOTION | DENSITY | TYPE | COLOR | 비고 |
|---------|----------|--------|---------|------|-------|------|
| `landing` | 6–8 | 5–7 | 2–4 | 6–8 | 5–7 | 히어로 예산 엄수, 시그니처 필수 |
| `portfolio` | 7–9 | 4–6 | 2–4 | 7–9 | 4–6 | 브랜드가 히어로급 신호 |
| `marketing` | 5–7 | 5–7 | 3–5 | 5–7 | 6–8 | 가짜 수치·존 도 금지 |
| `product` | 3–5 | 2–4 | 5–7 | 3–5 | 3–5 | 패턴 일관성·상태 UI 우선 |
| `dashboard` | 2–4 | 1–3 | 7–9 | 2–4 | 2–4 | 카드는 상호작용 단위일 때만 |

## 금지 목록 (요약 — AI 티)

그리기·리뷰 시 아래로 즉시 탈락시킨다. 전문: [anti-patterns.md](anti-patterns.md).

- 가운데 정렬 히어로를 **기본값**으로 쓰지 않기
- 똑같이 생긴 카드 세 장을 가로로 늘어놓지 않기
- 이미지+텍스트 좌우 교차 배치를 **세 번 연속** 쓰지 않기
- 대문자 라벨은 **세 섹션당 한 개**까지
- 흐르는 텍스트(마키)는 **페이지당 한 개**까지
- 보라색 네온 글로우, 근거 없는 수치(92%·4.1배 등), “John Doe” 같은 가짜 이름 금지
- 기본 스택 티(Inter/Roboto/Arial/system만), 크림+세리프+테라코타 클리셰, 퍼플 그라데이션 기본 테마 금지(기존 디자인 시스템 예외)

## 예외

- 오탈자·단일 파일 소규모 스타일(`AGENTS.md` 직접 처리 예외)은 생략 가능
- 기존 디자인 시스템이 확정된 brownfield 부분 수정(E2E lifecycle 밖)은, 변경 화면에 영향 있는 축만 짧게 적어도 된다
